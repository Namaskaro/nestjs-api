# Review Intelligence V2 Live Testing

Локальный магазин для ручной проверки Review Intelligence. Профиль запускает
штатные модули Nest и Next dev из соседнего worktree `../frontend`. PostgreSQL
15 и Qdrant берутся из Shared Integration Test Environment. Redis создаётся
отдельно по закреплённому digest, с тестовым паролем и временным хранилищем.
Приложения слушают только `127.0.0.1`.

## Команды Windows

Запускайте из backend worktree `feature/review-intelligence-v2`. Нужны Node.js
24, установленные зависимости обоих worktree, локальный Docker Desktop и
Compose, как в [инструкции Shared Integration](../README.md). Для команды
`browser` нужен установленный Cypress.

```powershell
npm.cmd run review:live -- start
npm.cmd run review:live -- ready
npm.cmd run review:live -- seed
npm.cmd run review:live -- smoke
npm.cmd run review:live -- browser
npm.cmd run review:live -- stop
```

Первые две команды печатают `shop` и `api` для текущего запуска. `ready`
проверяет доступность каталога Next и подключения Nest к PG, Qdrant и Redis.
`start` проверяет миграции и автоматически заполняет данные. `seed` повторяет
заполнение с теми же ID, сохраняя уже изменённые отзывы. Для возврата к
исходному набору используйте `reset`, затем `start`.

```powershell
npm.cmd run review:live -- reset
npm.cmd run review:live -- start
```

`stop` завершает процессы приложений и Redis, сохраняя тестовые тома PG/Qdrant.
`reset` останавливает магазин и удаляет только ресурсы аттестованного Compose
project этого worktree. Данные ручной проверки на этом стенде будут удалены.
Параллельные тесты на другом стенде запускаются из отдельного worktree.
Во время работы магазина используйте его команды остановки и сброса.

Профиль получает порты и ключ Qdrant от runner. Ключи JWT и сессии создаются
для запуска. Рабочие `.env` не используются. Старт проверяет отсутствие
загружаемых Next dev `.env` в frontend worktree. Диагностика находится в
`backend/.tmp/review-live/store.log`. При повторном запуске порты могут
измениться. Открывайте новый `shop` и входите заново.

## Ручная проверка

Для обновления уже заполненного стенда выполните `stop` и `start`.
Откройте адрес из `ready` и войдите заново. Отзывы и сообщения чата остаются
в PostgreSQL. Для нового отзыва выберите купленный товар без своего отзыва.

Откройте `/login` на адресе `shop`. Общий пароль синтетических аккаунтов
`ReviewLive26!`.

| Роль | Email |
| --- | --- |
| Покупатель | `buyer@review-live.invalid` |
| Менеджер | `manager@review-live.invalid` |

1. Под покупателем откройте `/catalog`, затем «Кроссовки Альфа». На свежем
   стенде у товара 22 опубликованных отзыва разных покупателей, отдельные
   ожидающий и отклонённый отзывы. У покупателя есть доставленная покупка.
2. Проверьте статистику, «Показать ещё», сортировку и кнопку «Полезный отзыв».
   Отправьте новый отзыв. В личном блоке появится статус ожидания, публичный
   счётчик сохранит 22.
3. В отдельном окне InPrivate/Incognito войдите менеджером. Откройте
   `/admin/reviews` и одобрите отправленный отзыв по тексту. Обновите страницу
   товара в окне покупателя. Публичный счётчик станет 23.
4. В окне покупателя откройте «Чат поддержки» и отправьте по порядку:

   - «Подбери кроссовки для прогулок».
   - «Покажи отзывы о первом товаре. Удобно ли ходить?».
   - «Сравни товары 1 и 2».
   - «Порекомендуй товар 1 или 2 с учётом отзывов».
   - «Порекомендуй товар 3 для прогулок».

   Ожидаются три товара, ответ с карточками источников и впечатления
   покупателей из Summary, затем строки средней оценки и количества оценок
   в сравнении. В рекомендации каталожное обоснование и отзывы показаны
   отдельно. У Гаммы есть обоснование, опубликованных оценок пока нет. У Альфы
   сводка уже сгенерирована на старте. Индексация новых публикаций и
   последующее обновление сводки выполняются действующими воркерами.

`smoke` проверяет реальные HTTP и WebSocket с тестовыми аккаунтами.
`browser` проходит сценарий в Cypress через реальный API, без подмены
ответов. Проверки предполагают исходный набор и меняют тестовое состояние.
Для повторения точных исходных счётчиков используйте `reset` и `start`.

## Ограничения профиля

AI-модель, embedding и reranker детерминированы. OAuth, отправка писем,
оплата и прочие внешние операции магазина исключены из тестового профиля.
Профиль проверяет ручные сценарии Review Intelligence через Next dev.
Ошибки production build `/auth/password-reset` и общего TypeScript в
`ResetPasswordForm` остаются известными ограничениями frontend baseline.

Точка выбора AI находится в `live/ai.cjs`, wiring в `live/backend.cjs`.
Сейчас runner принимает только детерминированный профиль. Для следующей
проверки качества потребуется отдельно согласованный запуск с явным
бюджетом, отдельной передачей ключей и новым тестовым набором индекса и
Summary для выбранной модели. Режим реального провайдера требует отдельной
активации. Автоматического перехода к нему нет.

Готовность этого стенда относится к пользовательской проверке.
Вопросы переносимости описаны в [RELEASE_GATE](../../../docs/review-intelligence-v2-integration.md).
