## 1. Цель
Объединить утверждённые версии Review Intelligence V2, Agentic Memory V1 и существующего Support Engine в один проверенный Release Candidate. Это не автоматическое развёртывание или merge в main.

|---|---|---|---|
| Backend | TO_VERIFY | TO_VERIFY | TO_VERIFY |
| Frontend | TO_VERIFY | TO_VERIFY | TO_VERIFY |

У Review Intelligence отдельные SPEC/PLAN/STATE могут отсутствовать. Его входные доказательства: Git, отчёты о тестах и пользовательская приёмка; не создавать фиктивных источников.

## 3. Пользовательский результат
- Подбор товаров, Review Q&A, сравнения и рекомендация работают вместе.
- Существующий пользователь может явно продолжить правильный эпизод подбора и получить новую актуальную выдачу.
- Новый независимый подбор не наследует критерии прошлой задачи.
- Обработка удаления/изменения отзывов и памяти не возвращает старые данные.
- Auth, OrderAgent, handoff и существующий чат сохраняют поведение.

## 4. Обязательные критерии приёмки
- Интеграционные Git-ревизии точно определены для backend и frontend.
- Изолированная PostgreSQL успешно применяет цепочку миграций объединённой версии.
- Подтверждены необходимые Qdrant/Redis/worker контракты.
- Целевые тесты и ключевые межфункциональные сценарии прошли.
- Один локальный магазин успешно запущен с настоящим API/JWT/WS и доступен для пользовательской проверки.
- Результат ручной приёмки записан, критичные дефекты закрыты.
- Зафиксирован план выпуска/отката. Никаких production операций без отдельного разрешения.

## 5. Режим и независимые заключения
`INTEGRATION_STATUS` — техническая и пользовательская готовность совместной версии.
`PRODUCTIZATION_STATUS` — **отдельный** результат productization-audit для REUSABLE_PRODUCT. Если статус NOT READY, нельзя объявлять переносимый релиз готовым; отдельно допускается рассмотрение пилота для NextShop при выполнении его требований.

## 6. Разрешения и запреты
- Работа только в согласованных integration worktrees и изолированной тестовой инфраструктуре.
- Запрещены push, merge в main, deployment, изменение рабочих данных и платные AI-вызовы без отдельного разрешения.
- Не изменять исходные feature worktrees без утверждения.

## 7. Не входит в scope
- Новые функции и отдельная реализация User Context/Recommendations/Store Events.
- Переработка архитектуры исходных функций без отдельного решения.
- Production deployment до отдельного approval.
