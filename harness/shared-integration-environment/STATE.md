## Фактическая проверка

- Windows 10 22H2 (`10.0.19045`), Node.js `24.3.0`, npm `11.21.0`, Docker Engine `29.5.3`, Compose `5.1.4`. Сервисы — PostgreSQL `15.18`, pgvector `0.8.5`, Qdrant `1.19.0`.
- `npm ci`, `npm run build` и `node --check` для трёх новых `.mjs` завершились с кодом `0`.
- `up → ready → migrate → collections → seed → test → contract` завершились с кодом `0`. Prisma применила 32 из 32 миграций с пустого тома. Проверены pgvector, CRUD `User`/`Chat`/`SupportCase`, `UNIQUE`, `FOREIGN KEY`, видимость между двумя сессиями и rollback, косинусное ранжирование Qdrant, payload-фильтр, удаление и повторное чтение.
- `stop → up → test` прошли на новых localhost-портах и со старым seed. При повторном `migrate` Prisma сообщила `No pending migrations to apply`. Повторные `collections`, `seed`, `test` и `contract` прошли. `reset` из остановленного состояния аттестовал сервисы и удалил только тестовые ресурсы. Повторный `reset` завершился с кодом `0`. После удаления томов ещё один чистый цикл применил все 32 миграции и снова прошёл `test` и `contract`.
- Второй локальный проект `support-engine-it-ad98941a0bc1` поднялся одновременно с `support-engine-it-a31ebb8e7b2f`. Тот же runner применил отдельную миграцию `20261110000000_alternative`, создавшую `TicketImport(externalKey BIGINT, sourcePayload JSONB)` с искусственной записью. Прочитана запись `7 / {source: "synthetic-import"}`. Тот же `contract` прошёл без изменений. В корне второго хоста и рядом с Prisma-схемой лежали искусственные `.env` с разными непригодными `POSTGRES_URI`. Они не повлияли на deploy. Переданные из оболочки `COMPOSE_PROJECT_NAME` и `SUPPORT_ENGINE_IT_KEY` также не меняли вычисленный проект и ключ.
- Отрицательные проверки вернули код `1` до мутации. `NODE_ENV=production` отклонил `migrate`, заданный `DOCKER_HOST` отклонил `reset`, тестовый том с посторонней меткой остался на месте после отклонённого `reset`, изменение текста уже применённой миграции отклонено по SHA-256.
- После проверки обоих проектов их контейнеры, сети и тома отсутствуют. До и после совпали Docker ID, время запуска и монтируемые volumes `guest_pg` и `guest_qdrant`. Для рабочих экземпляров использован только Docker inspect метаданных.
