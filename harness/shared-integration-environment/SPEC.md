# Shared Integration Test Environment

Режим `REUSABLE_PRODUCT`. Задача и границы работ заданы запросом пользователя от 10 ноября 2026 года.

## Продукт

Разработчик Support Engine поднимает из корня проекта реальные тестовые PostgreSQL и Qdrant и использует их для повторяемых интеграционных проверок. Поставка включает отдельный Docker Compose, команды для PowerShell и npm, синтетические фикстуры и smoke-проверки. Хост предоставляет Docker Desktop с локальным Linux Engine, Node.js, зависимости из lockfile и свои Prisma-схему и миграции.

Общие команды управляют сервисами и подтверждают их изоляцию. Прикладные фикстуры текущей ветки подключаются отдельно. Смена структуры данных другого хоста не должна требовать изменения управления сервисами или базовых проверок их контрактов.

## Критерии приёмки

- PostgreSQL 15 с `vector` и Qdrant фиксированной версии запускаются в отдельном Compose project. Сервисы используют отдельные volumes и сеть, публикуют свободные порты только на `127.0.0.1` и проходят health checks.
- Из PowerShell и через npm можно запустить сервисы, подтвердить готовность, применить миграции, подготовить коллекции и данные, запустить smoke, остановить стенд и явно очистить тестовые данные. Рабочие `.env` не нужны.
- Перед записью, миграциями и очисткой команды проверяют Docker project, окружение, адреса и идентичность тестовых сервисов и БД. Несовпадение останавливает операцию. Рабочие контейнеры и их volumes остаются нетронутыми.
- PostgreSQL-проверки используют реальные миграции текущей ветки, CRUD, ограничения и две транзакционные сессии для наблюдения изоляции и rollback. Ошибка исторической миграции фиксируется с именем миграции и фактической причиной. История миграций сохраняется.
- Qdrant-проверки используют реальные коллекции и детерминированные векторы. Проверяются поиск ближайшего вектора, фильтрация payload, удаление и повторное чтение.
- Выполняются чистый запуск, повторный запуск, проверка безопасной очистки и проверка переносимости на независимо устроенных синтетических данных. Результаты и ограничения фиксируются в `STATE.md` и аудите.

В область задачи входят только тестовые ресурсы и искусственные данные. Платные запросы, рабочие и production-сервисы, Review Intelligence, Agentic Memory, User Context и рекомендации вне области. После успешной проверки предусмотрен локальный коммит в выделенной ветке.
