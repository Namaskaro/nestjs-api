Реализован backend отзывов и ручной модерации. Этапы 2–6 не реализованы.
Изменения сделаны в `feature/review-intelligence-v2` от

## Правила и архитектура

Автор определяется существующим `JwtAuthGuard` и `CurrentUser('id')`.
Backend ищет заказ именно этого пользователя со статусом `DELIVERED`
и соответствующим productId в JSON items, затем проверяет items через
существующий `OrderItemRecordSchema`. Проверка выполняется при создании
и повторно перед одобрением основного отзыва. `OrdersService` не изменён.

Обязательны целая оценка 1–5 и текст 1–4000 символов после нормализации NFC,
переводов строк и обрезки внешних пробелов. Проверки содержательности и AI-модерации нет.
Создание всегда переводит материал в `PENDING`. Решение `PUBLISHED` или
`REJECTED` принимают существующие роли Admin/Manager; причина ограничена 500 символами.
Повтор того же решения идемпотентен, противоположное решение возвращает 409.
Пересмотр уже завершённой модерации в этом этапе не предусмотрен.

На пользователя и товар сохраняется один Review-слот. Удаление помечает его
`deletedAt`; повторное создание выдаёт новый `publicationId`, дату подачи и
`PENDING`. Старые дополнения удаляются при повторном создании, голоса очищаются
при удалении и повторном создании; счётчики обнуляются. Автор может удалить
также ожидающий или отклонённый отзыв. Редактировать тексты нельзя.

Дополнения разрешены автору опубликованного действующего отзыва, имеют
собственную дату и независимо проходят модерацию. Удаление родительского
отзыва сразу исключает все его дополнения из публичного чтения.

Все записи выполняются короткими Prisma-транзакциями `Serializable`.
Условные обновления используют `stateVersion`, состояние и `publicationId`.
Запоздалая операция старой публикации получает 409; сериализационный конфликт
`P2034` также возвращается как 409 без автоматических повторов.

Один `review-publication.ts` задаёт публичные условия и проекцию для ReviewsService
и вложенных reviews во всех затронутых чтениях ProductsService. Выдаются только
`PUBLISHED`, неудалённые, подтверждённые материалы. Дополнения дополнительно
сверяются с текущим publicationId родителя. Данные автора ограничены id/name/image.
Для совместимости `createdAt` основного публичного отзыва означает дату публикации.

## API

| Маршрут | Доступ | Назначение |
| --- | --- | --- |
| `GET /reviews/:productId` | Публичный | Массив опубликованных отзывов и дополнений |
| `GET /reviews/:productId/mine` | JWT | Свой текущий отзыв, canCreate и reason |
| `POST /reviews/create` | JWT | `{ productId, rating, text }`; userId/status клиента игнорируются |
| `POST /reviews/:reviewId/addenda` | JWT, владелец | `{ publicationId, text }` |
| `DELETE /reviews/:reviewId?publicationId=...` | JWT, владелец | Удаление, 204 |
| `GET /reviews/moderation?kind=review` | Admin/Manager | Первые 50 ожидающих основных отзывов, старые первыми |
| `GET /reviews/moderation?kind=addendum` | Admin/Manager | Первые 50 ожидающих дополнений к действующим опубликованным отзывам |
| `PATCH /reviews/moderation/reviews/:reviewId` | Admin/Manager | `{ publicationId, decision, reason? }` |
| `PATCH /reviews/moderation/addenda/:addendumId` | Admin/Manager | То же решение для дополнения |

Пагинации отзывов, голосования и статистики в этом этапе нет. Ограниченная
очередь модерации последовательно освобождается решениями по текущим материалам.
Существующие способы пагинации товаров сохранены.

## Prisma и миграция

Добавлены ReviewAddendum, ReviewVote и ReviewSummary; Review расширен метаданными
публикации, покупки, модерации и согласованными полями будущих этапов.
ReviewVote/ReviewSummary пока имеют только структуру: сервисов голосования,
индексации и генерации нет. Nullable userId/productId старых строк сохранены
для совместимости; новые записи сервиса требуют оба значения, публикация
без них запрещена. Количество shipments у Order не менялось.

`prisma/migrations/20261108000000_review_intelligence_v2_stage1/migration.sql`
подготовлена как scoped diff от Prisma schema указанного baseline. Она атомарна:
блокирует запись в Review, останавливается при дублях ненулевой пары user/product,
заполняет старые publicationId UUID и submittedAt из created_at, сохраняет старые
тексты/оценки в PENDING и создаёт индексы, FK и CHECK для опубликованного содержания.
Автоматического удаления дублей или публикации старых отзывов нет.

Миграция **не применялась**. Обнаружены только рабочие PostgreSQL-базы,
отдельной проверенной тестовой базы нет. Перед применением требуется выделенная
тестовая БД, проверка её фактической схемы и прогон переноса старых строк,
отказа при дублях, unique/CHECK/FK и конкурентных сценариев. Историческая цепочка
миграций не использовалась как эквивалент текущей schema; её воспроизводимость
с нуля этой задачей не установлена. Рабочая БД и конфигурация не изменялись.

## Проверки и ограничения

`prisma validate` и `prisma generate` завершились успешно без подключения к БД.
`npm run build` прошёл. Целевой Jest-прогон двух новых файлов: **40/40**.
Тесты покрывают ownership, доставку, дубли, обязательные поля, PENDING,
одобрение/отклонение, дополнения, удаление/повторное создание, старый publicationId,
guard/roles, отсутствие маршрутов редактирования и публичные запросы каталога.

Использованы небольшие локальные Prisma/service mocks и существующий Nest/Jest/
Supertest. Реальный RolesGuard исполнялся; JWT заменён тестовым guard по образцу
существующих HTTP-тестов Orders. Сервисы AI/S3 в каталожном тесте не создаются.
Моки не доказывают исполнение JSON-фильтра, изоляцию транзакций и ограничения БД.

Первый прогон: 39 успешных тестов и один ECONNREFUSED из-за преждевременного
создания нескольких Supertest requests. Запросы сделаны последовательными,
проверки доступа сохранены; повторный прогон успешен. Удалены только конечные
пробелы в добавленных комментариях generated index.d.ts, обнаруженные diff-check.
Финальный review также выявил потерю прежнего `relativeEnvPaths.schemaEnvPath`
в generated index.js/edge.js из-за генерации в worktree без .env. Существующий
путь `../../.env` сохранён в метаданных клиента без чтения/копирования окружения
и изменения конфигурации приложения. Открытых исправимых дефектов review нет.

Ручных end-to-end сценариев с реальным JWT и PostgreSQL не выполнялось.
Проведена ручная проверка кода, SQL и итогового diff. Полный запуск приложения,
миграция, реальный PostgreSQL и конкурентные гонки остаются непроверенными.
Frontend, AuthModule/guards, OrdersService, Product Search, ChatService,
Support Graph и AI Provider не менялись.

Результат этапа передаётся с успешными доступными проверками и блокером DB-проверки.
Полная готовность и пользовательская приёмка пока не заявляются.

## Зафиксированные решения будущих этапов

- Summary: первые 10 основных опубликованных отзывов разных покупателей;
  затем +10 до 100, после 100 — примерно +10%. Дополнения не запускают пересчёт,
  но все актуальные опубликованные дополнения входят в следующий плановый запуск.
  Удаление учтённого отзыва инвалидирует сводку и при необходимости запускает пересчёт.
- Будущий обработчик: polling около 30 секунд, восстановление после рестарта
  и корректный lease при длительном LLM-запросе. Сейчас обработчика нет.
- Recommendation: расширить контекст существующего LLM-вызова Synthesizer готовым
  рейтингом/summary; отдельного текста впечатлений и Qdrant-поиска обычной рекомендации нет.
- Review Q&A: небольшой тематический retrieval и один LLM-вызов при необходимости,
  внутри консультации, без отдельного Review Agent.
- Compare: только средний рейтинг; без summary и дополнительных LLM-вызовов.
- Историю старых текстовых сообщений не переписывать. Удалённые отзывы исключаются
  из новых ответов; отдельная старая карточка может показывать недоступность источника.
  ChatService и Support Graph ради пересмотра истории не изменяются.
