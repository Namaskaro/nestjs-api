# Review Intelligence V2 — границы Support Engine

Review Intelligence читает опубликованные ревизии, считает статистику,
обновляет индекс и сводки и возвращает проверяемые источники ответов.
NextShop отвечает за создание, право на отзыв, авторство, покупку и модерацию
в своём каталоге. Эту ответственность другой магазин может оставить у себя.

## Границы и подключение

| Граница | Контракт | Адаптер NextShop и инфраструктура |
| --- | --- | --- |
| Публичные отзывы | `ReviewSourcePort` возвращает текущие `PublishedReview` и сообщает о наличии опубликованного корпуса | `NextShopReviewSource` нормализует Prisma Review и дополнения. Существующий фильтр опубликованности сохранён |
| Товар | `ReviewProductLookup` проверяет доступность идентификатора для поиска по отзывам | NextShop Prisma Product. Product Consultant продолжает получать подробности через собственный каталог и действующий `ProductDetailsPort` |
| Статистика и готовая сводка | `ReviewExperiencePort` читает проекции одним снимком | `NextShopReviewSource` использует PostgreSQL Repeatable Read. `readReviewExperience` и правила подсчёта общие |
| Хранение производного состояния | `ReviewIndexJobs` и `ReviewSummaryJobs` хранят задания, lease, ревизии и результаты | `PrismaReviewJobs` использует прежние таблицы, условия записи и снимки. Новой миграции нет |
| Поиск и запись вектора | `ReviewVectorIndex` возвращает ссылки, версии и страницы для очистки | `QdrantReviewIndex` использует существующий `QdrantService`. Проверка источника остаётся у авторитетного источника отзывов |
| Модели | `ReviewTextModels` и `ReviewEmbeddings` принимают запросы к модели и возвращают результат без объектов провайдера | `AiReviewModels` сохраняет существующие `AiService`, STANDARD, token counter, structured output и embedding space |

`src/review-intelligence/core` содержит канонические источники, расчёт
рейтингов, правила переоценки evidence, пороги и планирование сводки.
`src/review-intelligence/application` содержит индекс, сводки, Q&A и чтение
review experience. NestJS-воркеры занимаются расписанием, конфигурацией,
логами и сопоставлением ошибок. HTTP-мутации в `ReviewsService` по-прежнему
работают в транзакциях NextShop, используя общую политику обновления сводки.
Авторитетное подтверждение покупки осталось в NextShop Order и JSONB.
ProductAgent получает `ReviewExperienceReader` и `ReviewEvidenceLookup`
через токены провайдеров. Рекомендация сохраняет один вызов синтеза.
Публичные DTO, WebSocket-артефакты и UI сохранены.

Подключающий код назначает доверенный `storeId` портам чтения, заданий и
индекса. Смешивание привязок отклоняется при создании индекса. Для каждого
магазина приложение получает только его авторитетные ревизии. Ссылка
сохраняет идентификаторы отзыва, публикации и источника. Редакция получает
новый publicationId. Отзыв публикации немедленно исключает её из чтения
источника, даже пока очистка вектора ждёт воркера. В той же транзакции
хранилище фиксирует изменение корпуса и применяет
`reviewSummaryAfterChange`. Снимок сводки и её условная запись привязаны
к lease и версии корпуса.

Совместимый профиль NextShop использует коллекцию `reviews` и БД одного
магазина. Для этого профиля каждый магазин должен получить отдельный
экземпляр или пространство Qdrant. Остальные привязки используют коллекции
по хешу `storeId`. Разделение коллекций задаёт область работы приложения.
Оно не заменяет ограничения доступа к самому Qdrant.

## Проверка переносимости

Существующий `npm.cmd run test:integration:reviews` проверяет NextShop на
PostgreSQL и Qdrant. Он же запускает независимый синтетический feed из
`infra/integration/review-external-fixture.cjs`. Feed использует SKU,
внешние ключи покупателей, последовательность изменений и редакции
публикаций. Его хранилище состояния находится в памяти процесса. Оно и
NextShop вызывают одни и те же `ReviewIndex`, `ReviewSummaries`, Q&A и
расчёт статистики. Сценарий сравнивает две реальные коллекции Qdrant с
одинаковыми ID и передаёт внешний review experience настоящему исполнителю
рекомендации. Подробные результаты прогонов хранятся в Harness.

| Пункт portability-checklist | Статус | Подтверждение и границы |
| --- | --- | --- |
| A. Core и application | PASS | Контрактный тест проверяет импорты. Ни Prisma, ни NestJS, ни SDK Qdrant не входят в переносимый слой. Локальная модель подставляется через порты |
| B. Интеграции | PASS для проверенных контрактов | NextShop и внешний feed дают разные формы записей. Feed проверяет публикацию, повтор и позднюю доставку, новую редакцию и отзыв публикации. Запись авторитетных отзывов остаётся у источника. Реальная авторизация и атомарные записи проверяются профилем NextShop |
| C. Клиент | PASS для совместимости | Существующие DTO и артефакты сохранены. HTTP, WebSocket и Cypress проверяют действующий NextShop. Версионирование и переносимость остальных транспортных контрактов Support Engine вне этого этапа |
| D. Данные | PASS для изолированных экземпляров, NOT VERIFIED для общей БД | Проверки NextShop используют прежний PostgreSQL и реальные lease, повтор и перезапуск. Внешний feed использует отдельное синтетическое хранилище и реальный Qdrant. Общая БД нескольких магазинов и долговечное хранилище второго адаптера не проверены |
| E. AI | PASS для контрактов, NOT VERIFIED для качества реального провайдера | Token budget, отбор источников и проверка после модели сохранены. Векторы сохраняют прежний идентификатор embedding space |
| F–G. Review Intelligence | PASS для двух тестовых подключений | Источники актуализируются, опубликованность проверяется повторно, редакции удаляют прежние векторы, Summary пересчитывается по тем же порогам. Внешний evidence проходит через рекомендацию с одним вызовом. Остальные возможности Support Engine вне аудита |

Ручная проверка запускается по [инструкции Review Live](../infra/integration/live/README.md).
Production-поставка требует долговечного хранилища для внешнего источника,
проверки установки и восстановления вне NextShop и проходящей frontend-сборки.
