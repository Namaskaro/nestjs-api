# Ручная проверка Review Intelligence с реальными AI-моделями

`LIVE_AI_VALIDATION: DEFERRED_TO_USER_MANUAL_TESTING`. Реальные модели,
embeddings и качество ответов ещё предстоит проверить. Инструкция использует
готовый CLI и синтетический корпус из 12 отзывов для двух товаров. Вводить
JSON, ID товаров и вопросы в консоль не требуется.

## 1. Поднять изолированный стенд

Откройте PowerShell в корне backend-worktree `feature/review-intelligence-v2`
и запустите Docker Desktop. Используйте существующие зависимости проекта.

```powershell
npm.cmd run integration -- up
npm.cmd run integration -- ready
node infra/integration/live-ai-run.mjs offline
```

Продолжайте после `offline: PASS`. Runner проверяет принадлежность
PostgreSQL и Qdrant тестовому Compose-проекту, создаёт свой синтетический
набор и отдельную коллекцию. В офлайн-команде модель и embeddings
подставные. Для оценки качества используйте команды следующего раздела.
Магазин, рабочие таблицы и frontend для этих команд запускать не нужно.
[Инструкция стенда](../infra/integration/README.md)

## 2. Выбрать существующий профиль

Подготовьте путь к локальному `.env` с существующим ключом, который
разрешён для тестов. Один файл может обслуживать несколько профилей.
Runner читает настройки провайдера из указанного файла. Если в текущем
PowerShell уже заданы одноимённые переменные окружения, они имеют приоритет.
Используйте чистую сессию и не копируйте ключи в Git, историю команд или
отчёт. Убедитесь, что списания относятся к разрешённому каталогу,
проекту или ключу. Если доступ или безопасный тариф для профиля не
подтверждён, пропустите его и отметьте `NOT VERIFIED`.

## 3. Запустить сценарии

После подтверждения конфигурации введите только путь к `.env`. Следующие
команды отправляют реальные платные запросы. Запускайте по одному профилю
и дождитесь выхода процесса. Для полного прогона начните с Yandex, чтобы
остальные модели могли использовать те же найденные источники.

```powershell
$reviewEnvPath = Read-Host 'Полный путь к существующему локальному .env'
$env:REVIEW_LIVE_AI_SCOPE_CONFIRMED = '1'
node infra/integration/live-ai-run.mjs report
```

Если журнал отсутствует и вы сверили, что оплаченных запросов в этой
кампании ещё не было, разрешите его создание один раз. При существующем
журнале этот шаг пропустите.

```powershell
$env:REVIEW_LIVE_AI_INITIALIZE = '1'
```

Выберите одну команду для запуска. Если у профилей разные файлы
конфигурации, измените `$reviewEnvPath` перед следующим запуском.

```powershell
node infra/integration/live-ai-run.mjs yandex $reviewEnvPath | Tee-Object -FilePath .tmp/review-live-ai-yandex.txt
node infra/integration/live-ai-run.mjs openai $reviewEnvPath | Tee-Object -FilePath .tmp/review-live-ai-openai.txt
node infra/integration/live-ai-run.mjs polza $reviewEnvPath | Tee-Object -FilePath .tmp/review-live-ai-polza.txt
```

Команда сама отправляет вопросы ниже и печатает ответы и источники.
Runner использует настоящий код сборки Summary, Q&A и синтеза Recommendation.
Если результаты Yandex/Qdrant недоступны, генерация Q&A может использовать
фиксированные опубликованные синтетические отзывы. Поле `evidence` в отчёте
указывает, какой режим сработал. Это позволяет оценить текст Q&A отдельно
от поиска. В таком режиме реальная семантическая релевантность остаётся
`NOT VERIFIED`.

## 4. Оценить результаты

Для генерации `REVIEW_OUTPUT` означает, что приложение вернуло результат.
Поставьте `PASS` вручную, если выполнены критерии в таблице. Поставьте
`FAIL` при неверном ответе или ссылках, которые его не подтверждают.
Если вызов пропущен либо доказательств недостаточно, отметьте `NOT VERIFIED`.

| Сценарий | Что отправляет runner | Что должно получиться |
| --- | --- | --- |
| Summary | Просит собрать впечатления по 10 опубликованным отзывам о кроссовках «Тропа». | Краткая сводка с положительными и отрицательными впечатлениями. Подтверждены комфорт на прогулке, тесная посадка у части авторов и опыт промокания. Без выдуманных свойств, долей и обещаний. |
| Q&A с источниками | «Удобно ли долго ходить по асфальту?» | Ответ о покупательском опыте. Источники могут включать отзыв о часе ходьбы без усталости, мягкой пятке и тесном носке после долгой ходьбы. Каждый источник в отчёте соответствует текущему опубликованному отзыву «Тропы» и подтверждает связанное утверждение. |
| Q&A при недостатке данных | «Подойдут ли для игры на снегу при минус двадцати?» | Прямо говорит, что в отзывах нет опыта для ответа про снег и мороз. Ссылки, если показаны, не выдаются за доказательство пригодности. |
| Recommendation с отзывами | «Какие кроссовки выбрать для часовых прогулок по городу?» | Рекомендует «Тропу» как городскую модель с лёгкой гибкой подошвой. Объясняет отличие от «Опоры» для силовых тренировок. Отзывы могут уточнить комфорт и посадку, а утверждения о товаре опираются на каталог. |
| Recommendation без отзывов | Тот же вопрос с теми же товарами, контекст отзывов убран. | Сохраняет содержательную рекомендацию и объясняет конкретное отличие двух моделей по каталогу. Без ссылок на отсутствующие отзывы. |
| Реальные embeddings и релевантность | По «Тропе» отправляет оба вопроса Q&A, «Удобно ли, если стопа широкая?» и «Промокают ли под дождём?». После отзыва публикации у «Опоры» спрашивает «Держит ли пятка на силовых тренировках?». | 12 векторов по 768 измерений. В `top3` минимум 3 из 4 попаданий. Для широкой стопы ожидается отзыв о тесной посадке, для дождя — отзыв о промокании. Вопрос про снег может остаться без релевантного результата. `filtered` и `removed` равны `true`: черновик, отзыв о другом товаре и отозванная публикация отсутствуют в соответствующей выдаче, а вектор отозванной публикации удалён. |

Фиксируйте отдельно YandexGPT, OpenAI и Qwen, затем реальные embeddings,
качество Summary, достоверность Q&A, качество Recommendation и релевантность.
Полный статус проверки требует фактического результата по каждому провайдеру.

## 5. Остановить и сохранить

После завершения профиля можно не запускать следующий. Для срочной
остановки нажмите `Ctrl+C` один раз. Уже отправленный запрос может быть
оплачен. Если журнал показывает `reserved` или `uncertain`, сохраните его
и сверяйтесь с биллингом перед продолжением. Блокировку и журнал вручную
не сбрасывайте, вызов автоматически не повторится.

```powershell
node infra/integration/live-ai-run.mjs report | Tee-Object -FilePath .tmp/review-live-ai-usage.txt
Remove-Item Env:REVIEW_LIVE_AI_INITIALIZE -ErrorAction SilentlyContinue
Remove-Item Env:REVIEW_LIVE_AI_SCOPE_CONFIRMED -ErrorAction SilentlyContinue
npm.cmd run integration -- stop
```

`report` читает локальный журнал, показывает input, output, reasoning
и расчёт в рублях по ставке резерва. Сохраните
`.tmp/review-live-ai-campaign-v1.json`, файлы отчётов и свои оценки.
Сверьте время, usage и фактические списания в кабинете. Остановка
сохраняет тома стенда и локальный журнал.
